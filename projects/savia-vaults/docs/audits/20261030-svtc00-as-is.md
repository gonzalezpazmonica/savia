## Cómo reproducir

```
cd projects/savia-vaults
npm ci --ignore-scripts                          # una vez
bash eval/audit-svtc00/run.sh all [dir-salida]   # 9 casos, ~6 s, exit 0 en la base auditada
bash eval/audit-svtc00/run.sh H6                 # un caso
AUDIT_STACK=1 bash eval/audit-svtc00/run.sh ...  # traza completa si falla
```

Cada aserción describe el comportamiento observado en la base auditada: si un cambio posterior lo altera, la aserción falla y obliga a revisar el veredicto. Alcance real de la comprobación de sensibilidad: `AUDIT_MUTATE_CHECK=<etiqueta>` invierte una aserción y confirma que esa línea puede fallar (probado con `H1`, `H1-unknown`, `H2-pair-negated`, `H2-id-absent-CT`, `H6`, `H6-default`, `H6-default-stale`, `surface-search-invalid`, `surface-a2a-invalid`); no demuestra que el resto de aserciones detecten una corrección real. Para H6 sí se comprobó contra código: neutralizar la revalidación de `rag/service.ts` (SE-481 R3) hace fallar `H6`.

Resultado en la base auditada: `H1..H8` y `surfaces` = PASS, exit 0, `environment.json` con `failed: false`. Un caso fallido escribe su JSON con `run: FAIL`, así que un directorio de salida reutilizado no conserva un PASS antiguo. El runner redirige `HOME` y las variables `SAVIA_*` a un directorio temporal propio (también en el proceso MCP hijo) y aborta si `os.homedir()` no queda dentro.

En la matriz de superficies, `invalid.md` (nivel `UNKNOWN`) no sale por `vault_search`, `vault_list`, `vault_rag` ni A2A `/search`.

## Hallazgos de seguridad

No se encontró fuga entre cúpulas ni bypass de ACL: `restricted` y `ungranted` quedan denegadas en las vistas MCP y A2A probadas; una nota N3 en cúpula N2 no sale por ninguna vista; la ACL de Files y el estado de las notas se revalidan al servir.

Abierto en la base auditada:
- **Fecha `valid_until` inválida** (severidad **Baja**): la nota se sirve como vigente. No cambia el nivel de confidencialidad; es un fallo de frescura.
- **Identificador inexistente** (calidad de recuperación): devuelve vecinos en lugar de abstenerse.

H1 (YAML roto, nivel desconocido) y H6 (revocación temporal) figuraban como abiertos en la tabla de SE-482 y los cierra SE-481; no quedan abiertos en esta base.
